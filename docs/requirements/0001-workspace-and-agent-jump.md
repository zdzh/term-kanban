# 需求文档：卡片 → 工作区 → agent

- 状态：草案（待确认，见 §11）
- 来源：看板里的卡片「看板支持跳转agent」（`cards.id = 4`）
- 相关：`CONTEXT.md`（术语）、`docs/adr/0001`–`0007`（既有架构决定）

---

## 0. 一句话

把看板从"记录任务"变成"驱动任务"：一张卡片能一键开出**隔离的 git worktree**并交给 agent（cmux / codex / vscode…），完成时按配置清理，卡片之间能挂关系并互相跳转。

---

## 1. 背景与现状

### 1.1 现在已有的（代码事实）

| 能力 | 位置 | 说明 |
|---|---|---|
| 分组（列）| `groups` 表 | 只有 id/name/position/archived_at，**没有任何配置字段** |
| 卡片 | `cards` 表 | 标题、Markdown 正文、二值完成、完成时间、归档、组内顺序 |
| 子任务 | `subtasks` 表 | 卡内一行检查项，**不可跳转、无工作区** |
| 动作 | `actions` 表 | **卡片级**命令/链接，点击执行；运行记录 + 日志文件（ADR-0006） |
| 让出终端 | `exec::run` + TUI | 交互式命令接管终端，输出同时 tee 到屏幕与日志 |
| 交互式命令识别 | `exec::infer_needs_terminal` | `ssh`/`vim`/`htop`/裸解释器等 |

### 1.2 缺口（正是这张卡提出的）

1. **分组没有配置**：不能关联 git 项目、不能定义组级按钮、不能挂完成钩子。
2. **没有"工作区"概念**：worktree 的创建、复用、清理全靠手工记。
3. **动作只能挂在单张卡上**：一个分组 10 张卡要配 10 遍同样的按钮。
4. **卡片之间没有关系**：不能表达"这张卡属于那张卡"，也不能跳转。

### 1.3 可以直接复用的地基

- `exec::run` 已经把"执行 → 日志 → 运行记录 → 退出码"做完了，新功能不需要另造执行层。
- 模板命令 + 变量替换是本次唯一的新机制，其余都是它的挂载点。

## 2. 需求拆解（原文 → 需求项）

原文五段，拆成 R1–R5。每条给出：意图、验收标准、边界。

### R1 分组配置

**意图**：分组从"纯容器"升级为"带环境的一列"，配置一次、组内所有卡受益。

**验收标准**
- 分组可配置：关联的本地 git 项目路径、工作区根目录、分支命名规则、组级按钮、完成钩子。
- 组内所有卡片自动获得该组的按钮，**无需逐卡配置**；配置变更后立刻生效（不复制到卡片上）。
- 配置非法时（路径不存在、不是 git 仓库、模板变量拼错）在保存时就报错，而不是等点击才炸。

**边界**
- 一个分组关联**一个** git 项目（多仓库见 §9 P1）。
- 分组配置与分组归档相互独立：归档分组不触发任何脚本。

### R2 分组按钮 / 工作区按钮

**意图**：把"打开任务的工作环境"变成一次点击。

**验收标准**
- 分组可定义若干按钮（标签 + 模板命令），组内卡片正面显示这些按钮。
- **工作区按钮**是内置语义，不是硬编码的命令：
  1. 确保该卡的 worktree 存在（不存在则 `git worktree add`，存在则复用）；
  2. 用配置的 `open` 命令打开它（`cmux {worktree}` / `code {worktree}` / `codex {worktree}` …）。
- **换工具只改配置**：把 `open` 改成 `codex {worktree}` 即可，不需要改代码、不需要重新编译。
- 重复点击是安全的：已有 worktree 直接打开，不重建、不报错。

**边界（明确不做）**
- 不绑定 cmux：代码里不出现 `cmux` 字样，只出现在用户配置里。
- 不管理 agent 进程本身（启动、停止、监控交给 cmux/codex）。

### R3 后置脚本（完成钩子）

**意图**：任务收尾自动化，典型场景是删掉对应的工作区。

**验收标准**
- 分组可配置 `on_complete` 钩子：模板命令 + `confirm` 开关。
- 触发时机：卡片**从未完成 → 完成**的那一次。取消勾选**不**触发反向钩子。
- `confirm = true` 时先弹确认框，显示将要执行的完整命令；拒绝则钩子不执行，但卡片仍是完成状态。
- 执行结果进运行记录与日志文件（复用 ADR-0006），失败时以 toast 报出退出码。

**边界**
- 钩子失败**不回滚**完成状态：你点了完成就是完成，脚本失败是另一件事。
- 钩子在后台捕获执行（不让出终端），避免打断你连续勾选。

### R4 任务关联

**意图**：卡片之间能表达关系，并能顺着关系跳过去。

**验收标准**
- 支持"卡片 A 关联卡片 B"，关系带类型；当前类型为**父子**。
- 详情里有「关联」区，可添加、删除、**跳转**（跳到目标卡片：切分组 + 选中 + 打开详情）。
- 卡片正面有轻量标记（如 `⤷2` 表示挂了 2 个关联）。
- 防环：A→B→A 这种成环的父子关系拒绝保存。

**边界**
- 关联是**弱链接**：归档/删除卡片不级联处理对方的关联，硬删除时清掉边。
- 关联不参与完成度计算（父子卡的完成互不影响）。

### R5 任务标题 ⚠️

原文只有一句"需要支持任务标题"。**当前卡片已经有标题字段**，且可 `i` 就地编辑、可搜索。因此这条需求目前**不可执行**，需要澄清（见 §11 Q2）。可能的解释：

- (a) 卡片正面标题被截断，希望显示更完整；
- (b) 想要多行标题 / 标题与正文分离得更彻底；
- (c) 指的是"任务"（卡片）在别处的标题，例如工作区窗口标题、cmux 标签名；
- (d) 只是草稿占位，可以删。

## 3. 术语与冲突（先统一，否则需求写不实）

| 你原文的说法 | 建议术语 | 说明 |
|---|---|---|
| 任务按钮 | **分组按钮**（Group Button）| 组级预设，自动出现在组内每张卡 |
| 任务管理项 / 关联命令 | **动作**（Action）| 已有术语，卡片级可点击命令或链接，保留 |
| 工作区 | **工作区**（Workspace）| 一张卡对应的一个 git worktree + 打开它的方式 |
| 后置脚本 | **钩子**（Hook）| 绑在生命周期事件上的模板命令，当前只有 `on_complete` |
| 关联、父子任务 | **关联**（Relation）| 卡片之间的有向边 + 类型 |
| 任务 / 条目 | **卡片**（Card）| 已有术语，继续用 |

### 3.1 一处必须解决的语义冲突

「**子任务**」和「**父子关联**」都带"子"，但它们是两件事：

| | 子任务（已有） | 父子关联（新增） |
|---|---|---|
| 是什么 | 卡片**内部**的检查项 | 两张**独立卡片**之间的关系 |
| 能跳转吗 | 不能 | 能 |
| 能有工作区吗 | 不能 | 各自都能 |
| 有正文/动作吗 | 没有 | 有 |
| 什么时候用 | "写周报"下的"收集数据/写正文/发邮件" | "重构 store 层"属于"重构计划" |

**结论**：这两个概念并存，命名必须拉开距离。建议对外一律说"子任务（清单项）"和"父卡/子卡（关联）"，避免都说"子任务"。

## 4. 核心设计：一个「模板命令」，三个挂载点

整份需求只引入**一个新机制**：模板命令。其余功能都是它的挂载点。

### 4.1 模板变量

| 变量 | 含义 | 例 |
|---|---|---|
| `{card_id}` | 卡片 id | `12` |
| `{slug}` | 由标题净化的短横线串（小写、去符号、截断）| `fix-nightly-ci` |
| `{title}` | 卡片标题原文（**仅用于显示，不插进 shell**，见 §7.3）| `修 nightly CI` |
| `{group}` | 分组名 | `本周` |
| `{repo}` | 分组关联的 git 仓库绝对路径 | `~/work/app` |
| `{repo_name}` | 仓库目录名 | `app` |
| `{worktree}` | 该卡工作区路径 | `~/work/app.worktrees/12-fix-nightly-ci` |
| `{branch}` | 该卡分支名 | `task/12-fix-nightly-ci` |

### 4.2 三个挂载点

1. **分组按钮** —— 组 → 组内所有卡（本次新增，R1/R2）
2. **卡片动作** —— 卡 → 该卡（已有，不动）
3. **钩子** —— 生命周期事件 → 卡（本次新增，R3）

> 由此得到一条重要推论：**"跳转到 agent"不是一个功能，而是分组按钮的一种配置**。要接 codex、vscode、新终端、甚至浏览器预览，都只是加一行配置。

### 4.3 配置示例（目标形态）

```toml
# 分组的配置，存在数据库里，但可导出/导入成这个文件（便于版本化）
[repo]
path          = "~/work/app"
worktree_root = "{repo}/../{repo_name}.worktrees"   # 默认值，可覆盖
branch        = "task/{card_id}-{slug}"             # 默认值，可覆盖

# 工作区按钮：内置语义「确保 worktree 存在 → 用 open 打开」
[[button]]
label = "工作区"
kind  = "workspace"
open  = "cmux {worktree}"        # ← 想换工具只改这一行

[[button]]
label = "VSCode"
kind  = "workspace"              # 复用同一个 worktree，只是换个打开方式
open  = "code {worktree}"

[[hook]]
event   = "on_complete"
run     = "git -C {repo} worktree remove --force {worktree}"
confirm = true
```

## 5. 数据模型变更

### 5.1 新增表

```sql
-- 分组按钮（组级预设，不复制到卡片）
CREATE TABLE group_buttons (
    id             INTEGER PRIMARY KEY,
    group_id       INTEGER NOT NULL REFERENCES groups(id) ON DELETE CASCADE,
    label          TEXT    NOT NULL,
    kind           TEXT    NOT NULL,            -- 'workspace' | 'command' | 'link'
    open_template  TEXT    NOT NULL DEFAULT '', -- kind=workspace 时用
    target         TEXT    NOT NULL DEFAULT '', -- kind=command/link 时用
    needs_terminal INTEGER NOT NULL DEFAULT 0,
    position       INTEGER NOT NULL
);

-- 完成钩子
CREATE TABLE group_hooks (
    id         INTEGER PRIMARY KEY,
    group_id   INTEGER NOT NULL REFERENCES groups(id) ON DELETE CASCADE,
    event      TEXT    NOT NULL,               -- 目前只有 'on_complete'
    run        TEXT    NOT NULL,
    confirm    INTEGER NOT NULL DEFAULT 1,
    position   INTEGER NOT NULL
);

-- 卡片 ↔ 工作区（一张卡一个工作区，见 §11 Q1）
CREATE TABLE card_workspaces (
    card_id        INTEGER PRIMARY KEY REFERENCES cards(id) ON DELETE CASCADE,
    repo_path      TEXT    NOT NULL,
    path           TEXT    NOT NULL,
    branch         TEXT    NOT NULL,
    created_at     TEXT    NOT NULL,
    last_opened_at TEXT,
    UNIQUE(path)
);

-- 卡片关联（有向边 + 类型）
CREATE TABLE card_relations (
    id         INTEGER PRIMARY KEY,
    from_card  INTEGER NOT NULL REFERENCES cards(id) ON DELETE CASCADE,
    to_card    INTEGER NOT NULL REFERENCES cards(id) ON DELETE CASCADE,
    kind       TEXT    NOT NULL,               -- 'parent_child'
    created_at TEXT    NOT NULL,
    UNIQUE(from_card, to_card, kind),
    CHECK (from_card <> to_card)
);
```

### 5.2 修改已有表

```sql
ALTER TABLE groups ADD COLUMN repo_path      TEXT;
ALTER TABLE groups ADD COLUMN worktree_root  TEXT;
ALTER TABLE groups ADD COLUMN branch_template TEXT;
```

### 5.3 迁移机制（必须补）

现在 `store.rs` 只有 `CREATE TABLE IF NOT EXISTS`，**没有版本号**，加列会失败。本次需要引入：

```rust
const SCHEMA_VERSION: i64 = 2;   // 用 PRAGMA user_version 记录
```

按版本顺序执行迁移，每步包在事务里；启动时若 `user_version > SCHEMA_VERSION`（被更新版本写过）则拒绝启动，避免旧版写坏新数据。

## 6. 交互设计

### 6.1 键位（不与现有冲突）

| 场景 | 键 | 作用 |
|---|---|---|
| 看板 | `g` | 打开当前分组的设置面板 |
| 看板 | `w` | 执行该组第一个「工作区」按钮（最常用，给个快捷键）|
| 详情 | `Tab` | 焦点循环：子任务 → 动作 → **关联** |
| 详情（关联焦点）| `r` | 添加关联（选目标卡片）|
| 详情（关联焦点）| `Enter` | 跳到关联的卡片 |
| 详情（关联焦点）| `d` | 删除选中的关联 |

现有占用（勿冲突）：`h l j k H L Tab Enter Esc q n i space e m a A v N R < > Backspace 1-9 /` + 详情里的 `t c y T d J K PageUp PageDown`。

### 6.2 卡片正面的信息密度

在现有「标题 / 进度+动作图标 / 子任务」基础上增加：

```
▎☐ 修 nightly CI
   ⎇ task/12-fix-nightly-ci  ●     1/3  $ ⎇ ⤷2
   ☑ 收集数据
```

- `⎇` 分支名：工作区已创建才显示，过长截断
- `●` 工作区有未提交改动（进 `git status` 探测，可配置开关）
- `⤷2` 关联数量
- 按钮图标最多 6 个，多出的收成 `+N`（沿用现有规则）

### 6.3 分组设置面板

整屏面板，分三段：仓库、按钮、钩子。字段少，用 `j/k` 选字段、`Enter` 编辑、`a`/`d` 增删按钮与钩子。

**保存时校验**：路径存在且是 git 仓库、模板变量名合法、`worktree_root` 不含未定义变量、分支名不含非法字符。

## 7. 安全与破坏性操作

### 7.1 模板命令就是任意 shell

沿用 ADR-0006 的约束：Web 版一旦暴露执行，必须只绑 `127.0.0.1` + token。分组配置属于"能执行代码的配置"，导出/导入文件时要提示这一点。

### 7.2 worktree 删除是破坏性的

- 默认 `confirm = true`（原文要求"支持命令执行前是否进行提示"）。
- **建议额外内置一道检查**：钩子执行前若 `{worktree}` 里有未提交改动，默认拒绝执行并提示（可配置 `--force` 覆盖）。删掉未提交代码是最容易后悔的操作。

### 7.3 变量注入

`{title}` 来自用户输入，直接插进 shell 等于注入面。规则：

- 插进命令的变量只允许 **已净化** 的：`{card_id}` `{slug}` `{repo}` `{worktree}` `{branch}` `{group}`（`{group}`/`{slug}` 走同一套净化）。
- `{title}` 只用于显示（确认框、卡片正面），**不参与命令拼接**；确实需要时用 `{slug}`。
- 所有路径变量做 shell 转义后再拼接。

### 7.4 并发

同一张卡连点两次工作区按钮：用 `card_workspaces.path` 的 UNIQUE + "先查后建、失败再查"处理，保证不会创建两个 worktree。

## 8. 实施分期（每期都能独立用）

| 期 | 内容 | 交付价值 | 预估 |
|---|---|---|---|
| **M1** | 分组配置（仓库路径）+ 分组按钮 + 模板变量替换 + 迁移机制 | 组内所有卡共享按钮，配一次管一片 | 中 |
| **M2** | 工作区：worktree 创建/复用 + `card_workspaces` + 卡片正面 `⎇` 状态 | **核心价值：一键进工作区** | 中 |
| **M3** | 完成钩子（含 confirm、脏检查、运行记录） | 收尾自动化，不再手工删 worktree | 小 |
| **M4** | 关联（父子）+ 详情关联区 + 跳转 | 多卡任务编排 | 中 |

依赖关系：M2 依赖 M1（模板与配置）；M3 依赖 M2（要删的是 M2 建的）；M4 独立。

## 9. 需求发散：让它更好用

按"投入产出比"分档，前两档建议做。

### P0（低成本、明显提升）

1. **工作区状态上卡面**：分支名 + 脏标记，一眼看出"哪个任务还开着"。
2. **按钮执行结果显示在卡片上**：最近一次执行 ✓/✗ + 退出码，按 `Enter` 进详情看日志。现在只有 toast，转瞬即逝。
3. **配置版本化**：分组配置存 DB，但支持 `kanban config export/import`，便于纳入 dotfiles 或与团队共享。
4. **`?` 帮助浮层**：键位已经 20+ 个，按 `?` 列出当前上下文的键位（看板/详情/归档各一套）。
5. **干跑（dry-run）**：首次执行某个按钮时，先显示完整命令等你确认一次，记住"以后不再问"。模板命令不透明，这一步能挡掉大部分配错。

### P1（进阶，价值明确）

6. **一卡多仓库**：分组关联多个 git 项目时，工作区按钮变成"打开全部"，一次开出多个 worktree（前后端联调场景）。
7. **工作区总览（`W`）**：列出所有活工作区、对应卡片、脏状态、最后打开时间，支持批量清理。
8. **完成前的脏检查**：勾选完成时若工作区有未提交改动，先提示而不是直接触发清理钩子。
9. **父卡显示子卡进度**：父卡正面显示 `子 2/5`，由关联自动汇总（不改变完成语义，只是展示）。
10. **归档联动**：归档卡片时提示"工作区还在，要一起清理吗"。

### P2（可选，锦上添花）

11. **agent 会话双向关联**：把 cmux 会话 id 存进 `card_workspaces`，可从卡片跳回正在跑的会话（这才是"跳转 agent"的完整形态）。
12. **时间统计**：已有完成时间，可加"从创建到完成"的停留时长，做周报。
13. **看板快照/导出**：导出为 Markdown 或 JSON，便于汇报或迁移。

## 10. 非功能需求

- **启动性能**：新增表与配置读取不得让启动超过 50ms（配置一次加载进内存，不要每帧查库）。
- **向后兼容**：老数据库（`user_version = 0`）必须能自动迁移，不丢任何卡片/子任务/动作/运行记录。
- **失败可见**：任何按钮/钩子失败都要留下运行记录 + 日志路径，不能只在屏幕上闪一下。
- **无守护进程**：不引入后台常驻服务，所有动作由用户操作触发。

## 11. 待澄清（每条附建议默认值）

| # | 问题 | 建议默认 | 影响 |

## 13. 与既有架构的关系

- **ADR-0001（core/TUI 分层）**：模板替换、worktree 管理、关联查询全部落在 `kanban-core`；TUI 只负责渲染按钮与发起意图。将来 Web 版直接复用。
- **ADR-0006（运行记录 + 日志）**：按钮与钩子都走同一套记账，不新增执行通道。
- **ADR-0003（分组不是状态列）**：分组现在多了一层"环境"含义（关联仓库），但**仍然是容器，不是进度**。这条不冲突，需在 CONTEXT.md 里补一句说明。
- **ADR-0004（子任务轻量）**：父子关联**不**复用子任务模型，两者独立（§3.1）。
- **ADR-0007（看板无删除键）**：钩子删除的是**工作区**，不是卡片，不违反该决定。
